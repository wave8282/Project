## 1. 요약

현재 저장소에는 관절 좌표 시퀀스 생성, 정상/낙상 데이터 결합, LSTM 분류, Autoencoder 재구성 오차 계산 코드가 존재합니다. 다만 데이터 라벨 생성과 평가 데이터 분리 방식에 중요한 위험이 있어, 현 상태의 학습 결과를 그대로 신뢰하기 어렵습니다.

이번 점검에서는 기존 실험을 임의로 바꾸지 않기 위해 모델 코드를 바로 덮어쓰지 않았습니다. 먼저 확인된 문제와 수정 순서를 문서화했습니다.

## 2. 확인된 문제

### P0. 낙상 라벨 생성 경로가 서로 모순됨

- `make_sequence.py`는 생성한 모든 시퀀스의 라벨을 `0`으로 설정합니다.
- 같은 스크립트가 결과를 `fall_X.npy`라는 이름으로 저장합니다.
- `make_lstm_dataset.py`는 `fall_X.npy`를 낙상 데이터로 간주해 라벨 `1`을 부여합니다.

따라서 파일 이름만으로 낙상 데이터라고 가정하면 실제 정상 데이터가 낙상(1)으로 라벨링될 수 있습니다. 입력 CSV가 실제로 어떤 행동을 담고 있는지, 영상 단위 라벨이 무엇인지 확인한 뒤 라벨을 생성해야 합니다.

**권장 조치:** 파일명으로 라벨을 추측하지 말고, 원본 영상별 명시적 라벨 메타데이터를 사용합니다. 정상은 0, 낙상은 1로 일관되게 생성하고 샘플 수와 라벨 분포를 출력해 검증합니다.

### P0. 겹치는 시퀀스가 학습/테스트에 동시에 들어갈 가능성

- `make_sequence.py`는 30프레임 창을 한 프레임씩 이동하며 만듭니다.
- 이렇게 만들어진 인접 시퀀스는 29프레임을 공유합니다.
- `fall_detection.py`는 시퀀스를 먼저 무작위로 학습/테스트 분리합니다.

같은 원본 영상에서 거의 동일한 시퀀스가 학습 세트와 테스트 세트에 나뉘어 들어가면 데이터 누수가 발생해 테스트 성능이 실제보다 높게 측정될 수 있습니다.

**권장 조치:** 시퀀스를 만들기 전에 원본 영상 단위로 train/validation/test를 분리합니다. 그 후 각 분할 안에서 시퀀스를 생성합니다. 같은 원본 영상이 여러 분할에 들어가지 않도록 영상 ID를 보존합니다.

### P1. Autoencoder 학습에 테스트 데이터가 섞임

- LSTM 분류 모델의 분리 이후, Autoencoder용 정상 데이터는 `X[y == 0]`에서 추출합니다.
- 이 배열은 학습/테스트 분리 전의 전체 데이터이므로 테스트 데이터의 정상 샘플도 Autoencoder 학습에 포함될 수 있습니다.
- 재구성 오차 임계값도 `X_test`의 평균과 표준편차로 계산합니다.

이는 테스트 데이터가 학습 또는 임계값 결정에 관여하는 평가 누수입니다.

**권장 조치:** Autoencoder는 정상 학습 데이터만으로 학습하고, 임계값은 별도로 분리한 정상 validation 데이터로 결정합니다. 테스트 세트는 최종 평가에만 사용합니다.

### P1. 경로가 특정 PC에 고정됨

`make_sequence.py`와 `make_lstm_dataset.py`에는 `D:/pose_project/` 경로가 직접 입력되어 있습니다.

**권장 조치:** 프로젝트 루트를 기준으로 상대 경로 또는 명령행 인자를 사용하도록 변경합니다.

### P2. 시퀀스 생성에서 마지막 창이 제외됨

`range(len(data) - sequence_length)`를 사용하고 있어, 일반적인 슬라이딩 윈도 기준으로 마지막 유효 30프레임 창이 생성되지 않습니다.

**권장 조치:** 입력 길이와 창 길이를 검증하고, 마지막 유효 창까지 포함하도록 수정합니다.

### P2. 데이터 결합 재현성 부족

`make_lstm_dataset.py`에서 `np.random.permutation`에 고정 시드를 사용하지 않습니다.

**권장 조치:** 재현 가능한 시드를 설정하고, 데이터 분할 및 라벨 분포를 기록합니다.

### P2. 평가 지표가 제한적임

현재 코드에서는 테스트 정확도 중심으로 결과를 출력합니다. 낙상 데이터가 상대적으로 적거나 오탐 비용이 큰 상황에서는 정확도만으로 모델을 평가하기 어렵습니다.

**권장 조치:** confusion matrix, precision, recall, F1-score, ROC-AUC(적절한 조건에서), 정상 영상 기준 오탐 횟수, 낙상 발생 후 탐지 지연시간을 함께 기록합니다.

## 3. 권장 수정 순서

1. 원본 CSV와 영상의 실제 라벨·파일 대응 관계 확인
2. 영상 단위 데이터 분리 및 라벨 메타데이터 설계
3. 시퀀스 생성 코드 수정(마지막 창 포함, 입력 형상 검사, 경로 설정)
4. 학습/검증/테스트 데이터 생성 및 누수 검사
5. LSTM 단독 기준 모델 재학습 및 평가
6. Autoencoder를 정상 학습 데이터로만 학습하고 validation 기반 임계값 설정
7. LSTM + Autoencoder 결합 모델 평가
8. 영상 단위 테스트 및 실시간 추론 코드 연결

## 4. 아직 확인이 필요한 사항

- `fall_data.csv`와 `pose_data.csv`는 저장소 목록에서 크기와 Git blob SHA가 동일한 것으로 확인되었습니다. 두 파일이 동일한 데이터라면 파일명만으로 정상/낙상을 구분할 수 없습니다.
- `X.npy`가 어떤 원본 영상과 라벨 규칙으로 생성되었는지는 현재 확인한 코드만으로 알 수 없습니다.
- 원본 데이터의 영상별 정상/낙상 구분표와 각 CSV의 생성 경위를 확인하기 전에는 라벨 생성 코드를 확정해서 수정하지 않는 것이 안전합니다.
- 실험에서 사용한 데이터 분할 방식이 기존 보고서의 수치와 동일한지 확인해야 합니다. 이 보고서는 저장소의 현재 코드 구조를 점검한 것이며, 과거 실험 수치를 재현했다고 주장하지 않습니다.
